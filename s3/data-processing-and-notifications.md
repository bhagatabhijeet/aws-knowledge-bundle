# Data Processing & Notifications — the Warehouse Comes Alive

## 🔔 Event Notifications: the doorbell

**S3 Event Notifications** ring a doorbell — automatically — the instant something happens to an object: a new box arrives (`PUT`), a box is thrown out (`DELETE`), or a box's edition changes (a new version created). The doorbell can ring three different rooms:

| Destination | Typical use |
|---|---|
| **Amazon SNS** (topic) | Fan out one event to many subscribers at once |
| **Amazon SQS** (queue) | Buffer events for a worker process to consume at its own pace |
| **AWS Lambda** (function) | Run code immediately in response — e.g., generate a thumbnail the moment an image is uploaded |
| **Amazon EventBridge** | Route events through rich filtering into many possible AWS services |

**Mnemonic:** *"A box lands on the shelf, and the doorbell instantly tells whichever room is listening — no polling, no delay."* This is the backbone of countless "upload triggers processing" pipelines: upload a video → Lambda transcodes it → result lands in another bucket.

## 🔍 S3 Select: reading one paragraph without hauling out the whole book

Normally, reading part of a CSV or JSON object stored in S3 means downloading the **entire object** and filtering it yourself. **S3 Select** (and its Glacier equivalent) lets you run a **simple SQL-like query directly against the object**, and S3 returns only the matching rows/fields — the filtering happens inside S3, not after a full download.

```sql
SELECT s.name, s.amount FROM S3Object s WHERE s.amount > 1000
```

**Mnemonic:** *"Ask the warehouse clerk to read you just the one paragraph you need from inside the box, instead of shipping the entire book to your desk first."*

This dramatically cuts both data transfer and processing time/cost for workloads that only need a slice of large structured files (CSV, JSON, Parquet).

## 📋 S3 Batch Operations: a crew, not one clerk

Doing something to **one** object is a single API call. Doing the same thing to **millions** of objects — copying them, tagging them, restoring them from Glacier, invoking a Lambda per object — is what **S3 Batch Operations** is for.

You supply:
1. A **manifest** (a list of objects — often generated by [S3 Inventory](monitoring-and-cost-optimization.md))
2. An **operation** to apply to every object in that list (copy, tag, ACL update, Object Lock retention, restore, or invoke a Lambda function)

**Mnemonic:** *"Instead of one clerk visiting a million boxes one at a time, hand a whole crew the same list and the same instructions, and let them work in parallel."* S3 tracks progress, retries failures, and gives you a completion report — essential for anything at real scale (a manual loop calling the API a million times will be slow, fragile, and easy to rate-limit yourself into trouble with).
